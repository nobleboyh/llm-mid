How prompt caching works — and how we verified it
Providers cache the shared prefix. Headroom is built to never touch it.
1Prefix caching, in one request
Call 1 — cold cache
FULL PREFILL · system prompt + tools + history
Provider computes K/V for every token. Slow, full price.
Call 2 — same prefix, warm cache
CACHE READ · reused K/V
new turn
Only the new suffix is prefilled. ~10–20% cost on the reused part, big latency win.

Why a proxy, not a mock: swapping GateMid's base_url to a mock would freeze any live session using it. The forwarding proxy sits in front of the real API and only logs — every request still gets a real answer, so we captured 8 A–H test pairs from genuine traffic and diffed the hot-zone bytes with zero downtime.
